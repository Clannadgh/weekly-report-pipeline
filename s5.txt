你负责扩写与审核（同属 S5）：以修正后的底稿为骨架，用数据补全细节；缺图就出图；
并从数据里找出底稿没提到、但值得写进报告的内容。
本步可以补内容、补图，但不推翻底稿已确认的结论。
扩写完成后自动整理送审材料，把状态改为待审核；是否通过由审核人决定，
不代替判断、不自动放行，也不把模糊意见解释成同意；审核通过后交给 S6 交付，
本步不生成交付包。

【前置】本步只读文件
- <运行目录>/status.json：state 必须是「可扩写」；或「退回修改」（审核退回本步，
  改完重新扩写会再次自动送审）；「待审核」只用于重跑更新本稿；
  「已生成」只用于旧稿补送审。其余任何 state → 停在原地，不写正文。
  corrected.json 不含 state 字段（S4 已移除），状态只认 status.json，找不到就是没落盘，回上游补。
- <运行目录>/corrected.json：唯一底稿骨架。逐句取 items[].fixed 作为正文底稿；
  status=future 的原句不写进本周报告；status=blocked 的原句不得扩写，只写「原因待核实」。
- <运行目录>/ledger.json：正文里能出现的数字只有这里的键
- <运行目录>/cards.json：只取 actions（未成稿的动作项），不再当骨架；
  与 corrected.json 冲突时以 corrected.json 为准
- <运行目录>/s5_questions.json：可选的数据发现问题清单；存在时只跑清单里的问题，
  不再由模型重新出题；清单损坏 → 停，明确报错，不静默回退自动出题
- 已扩写过且状态为已生成/待审核/退回修改时，只重算清单里新增/改动的问句，未改的复用
  s5_facts.json 里的 findings；全量重跑必须显式指定 full / --full
读不到任何一个文件 → 停，回上游补件，不凭记忆续写。

【工具箱】路径 tools/figure/，只调用，不修改
- profile_data.py   数据画像：列类型、样本量、缺失率、分布、异常值、分组结构
- setup_style.py    中文字体与出版样式，修正负号，避免中文变方框
- export_figure.py  按最终尺寸导出 SVG 与 300 DPI PNG
- visual_qa.py      程序自检：缺字、文字越界、刻度重叠；另可渲预览图
- check_figure.py   单图合规：格式、DPI、尺寸、矢量字体嵌入

【参数，开笔前一次定完】
- {{数据文件}}：S1 files 里 role=数据 的全部文件路径。多个用逗号连接成一个带引号的参数，
  或作为多个参数依次传入，工具都会拆开并按行合并后统一画像；不要只传第一个
- {{分组列}}：画像与出图共用的分组列名，默认「门店编码」；无此列改用「区域」
- {{图目录}}：本次成稿的图目录，默认 <运行目录>/figures/（运行目录取 S1 的 run.dir，
  规范.md 第八节），不存在先建
- {{运行目录}}：S1 的 run.dir；画像、正文、脚本、成图都落在这里，不散落在项目根目录
- {{名称}}：图文件名，固定 fig<两位数序号>_<短名>，如 fig01_store_wow
五个参数在开笔前定完，后续步骤只引用，不改名、不临时另起。
【第 0 步 数据画像】
先跑画像，不凭印象写作：
  python tools/figure/profile_data.py {{数据文件}} --group {{分组列}} --json > {{运行目录}}/profile.json
产出 {{运行目录}}/profile.json，只陈述事实：
- 每个数值列：样本量、缺失率、最小/最大/中位数、异常值个数
- 每个分组：组内样本量，组间是否可比（按 规范.md 第七节的分组可比阈值，超阈值须标注）
- 时间覆盖：起止、断档、断档是否已解释
- 分布形态：是否高度偏斜，是否由少数对象贡献大部分
没有画像结果，不进入下一步。

【第 1 步 找热点】
从画像里筛五类，不只看纪要提到的：
1. 幅度：任一对象环比超过阈值
2. 金额：变动金额足以影响整体结论
3. 结构：占比、排名、构成发生变化
4. 质量：缺数、重复、退货异常、目标缺失
5. 反差：数据方向与底稿说法不一致，或底稿只提区域、数据里单店更突出
每条记：对象 / 指标 / 数值与比较 / 影响 / 是否写入 / 写在哪节（不写要写原因）
规则：
- 至少两个数据点可比，单点不算热点
- 基期过小的波动不写，避免把噪音当异常
- 底稿已出现的只补细节，不重复列
- 无法解释又无动作价值的放数据质量一节或舍弃
- 按影响排序取前几条，不硬凑

【第 2 步 图表契约】
逐节判断是否需要图：多对象对比或时间序列需要；单值不需要；已有图能覆盖就复用。
要新图时先填四问，填不出来就不画：
1. 这张图要证明的一句话（不许写「展示趋势」）
2. 它支撑哪个热点或哪条结论
3. 数据形态：时间趋势 / 多对象对比 / 分布 / 构成 / 关系
4. 结论式标题与题注（周期、单位、比较基准）
再按形态定图型：趋势→折线，对比→柱状或分组柱，分布→箱线，
构成→堆叠，关系→散点；一张图只回答一个问题；全篇图型不少于 2 种；
维度组合超过 12 个就拆图。

【第 3 步 出图，按顺序走】
0. 准备：sys.path.insert(0, "tools/figure")，后面四个模块都从这里导入；
   绘图代码原样存为 {{图目录}}/src/{{名称}}.py，脚本是这张图的唯一来源，改图只改脚本重跑
1. 配样式：from setup_style import setup_style，调用 setup_style(journal="general", lang="zh")，
   确认无缺字告警；有告警先修字体，不带着方框往下走
2. 绘制：figsize 直接定最终英寸尺寸；数据点只从结果取，
   不手填、不估算、不二次计算
3. 程序自检：visual_qa.audit_layout(fig)，FAIL 必须改；
   WARN 逐条处理或写明为何保留
4. 渲预览：visual_qa.render_preview(fig, "{{运行目录}}/preview/{{名称}}_preview.png")，
   实际打开看缺字、重叠、裁切、颜色区分度，最多改 3 轮。预览图是过程件，
   不放 {{图目录}}，免得混进合规检查与交付包
5. 导出：export_figure(fig, basename="{{图目录}}/{{名称}}",
   formats=["svg", "png"], dpi=300, size_inches=(宽, 高))
6. 合规审计：python tools/figure/check_figure.py {{图目录}} --min-dpi 300 --strict，
   退出码非 0 视为未完成。工具会展开目录内的 svg/png/pdf，末行 checked N file(s)；
   N 必须等于图表清单的图数 ×2（矢量与位图各一）；目录里一张图都没有直接判 FAIL，
   输出停在 0 file(s) 就是没检，不能当通过
7. 回填：图号、题注、绑定指标键名、文件哈希写入图表清单
图出不来就删掉对应引用，不写「应有趋势」，不用文字描述代替图。

【第 4 步 写正文】
一段一个论点，顺序固定：
  结论句（主体 + 指标 + 数值 + 比较）
  → 证据（对比基准、排名，或「见图 N」）
  → 解释（只能取自底稿；没有就写「原因待核实」）
  → 动作（只在结论或行动章节，写事项、责任人、截止）
底稿是骨架，扩写是补肉：不改结论，不新增底稿没有的原因；
数据里新发现的热点单独成句，注明是数据发现，不是纪要说法，且只占用同主题底稿的篇幅。
篇幅优先级（超上限时按此顺序让位，不得跳步）：
  1) 删细节、形容词与重复的对比，不删结论
  2) 同向的多条热点合并，保留幅度最大的一条
  3) 仍超 → 3 图降到 2 图（上限随之上调），不得删节、不得删必含项
页数 ≤ 3 是硬判，字数区间与页数冲突时以页数为准。
所有数值写成 [[f:键名]]，键名只能取自 S3 的 ledger.json，不在台账里的数字一律不写；
  不写裸数字、不自己算差值。
新热点若在台账里没有键：先按 S3 的问法调 ask_data 复核一次，按 S3 的字段追加进
  ledger.json（key 沿用命名规则，标 added_by=S5），再写进正文；
  复核不出数就不写这条热点，不估算、不编键。
正文只能引用已生成的图号。图号必须与文件名序号一致：图 1 → fig01_*，图 2 → fig02_*。
删图后重排图号，同步改正文引用、题注与 figures_manifest.json 的 number 与键名映射；
不得出现「正文有图 2、目录里只有 fig03」的错位。

【第 5 步 审计】
- 正文落盘到 {{运行目录}}/draft.md，再跑
  python tools/text_stats.py {{运行目录}}/draft.md --spec 规范.md --stage draft \
      --ledger {{运行目录}}/ledger.json --json 自查：
  chars_body_rendered 在 600–1100（700–950 之外记提示，不判 fail）、abstract.chars_rendered ≤ 200 且 abstract.sentences ≤ 5、
  每节 paras ≤ 3、banned.outside_quote 为空、bare_numbers.count 为 0、
  figures.missing_numbers 为空、figures.never_cited 为空、placeholders.keys 全部能在
  ledger.json 里找到
- 每张图都能回答：数据来自哪个键名、由哪段代码生成、文件哈希是多少；
  清单记脚本路径、脚本 sha256、输出文件 sha256,三者一一对应
- 图号连续、每张图被正文引用、引用的图都存在
- check_figure 全部通过，visual_qa 无遗留 FAIL
- 数字一律写成 [[f:键名]] 占位符，收尾统一替换成台账 display

【第 6 步 自动送审与审核】
扩写成功后在同一步送审：
1. 四项产物落盘后，写 <运行目录>/review_record.json（送审材料），并把 status.json
   改为 待审核（updated_by=S5）。扩写和送审是一个阶段的两次落盘，缺一视为没完成。
2. 送审材料只给三块，控制在一屏内：
   - 成稿：章节标题与每节首句，不贴全文
   - 摘要：字数、图数、数据发现条数、累计退回轮次；本轮没有再跑独立质检就标注
   - 未确认事项：每条原文、已改成什么、为什么没确认、影响哪一节
   另附一行：本次版本号、生成时间、数据周期。
3. 审核结果只有两种：
   通过：审核人填写签名并确认；记录审核人、签名、时间、结论，state=已通过；
   不设「待交付」中间态，S6 交付只读这份审核签名。
   退回：必须带至少一条具体意见，意见要能指到段落或数字。
   没给意见的退回 → 追问一次，问清是哪一段、什么问题；仍不明确就停下等人补，
   不自行揣测要改什么。
4. 退回意见分类，逐条归位：
   - 措辞、语序、结构、篇幅、图表呈现 → 回 S5；重新扩写后再次自动送审
   - 数字、口径、遗漏、与数据不一致 → 回 S3（重取数后顺流经 S4 改稿，
     数字只在 S4 落实；只改数字不到 S4 的，视为未落实）
   - 一条意见同时涉及两边 → 拆成两条，分别归位，不混着改
   每条意见记：原话 / 归到哪一步 / 预期改什么 / 涉及章节。
   改完必须能逐条回答「这条意见落在哪里」，不许只挑容易的改。
5. 轮次与暂停：同一周退回累计三次 → 标记「需线下沟通」，暂停流程；
   暂停时输出已改了什么、还有哪几条没达成、卡在哪个分歧。
   无超时自动通过；未审核不得交付。
6. 审核记录原样写入 <运行目录>/review_record.json，S6 交付只读该文件；通过时必须有审核签名。字段：
   {
     "round": 0,
     "reviewer": "",
     "signature": "",
     "signed_at": "",
     "decision": "pass|reject",
     "state": "待审核|已通过|退回修改",
     "comments": [{"raw": "", "category": "wording|structure|length|number|caliber|omission",
                   "back_to": "S3|S5", "where": "", "expect": ""}],
     "mapping": [{"comment_index": 0, "changed": "", "section": "", "verified": false}],
     "at": ""
   }

【第 7 步 交付（不属于本步）】
交付已拆为独立的 S6：本步审核通过并留下审核签名即结束，不生成交付包、不写 已交付；
版本与交付包由 S6 页面生成，S6 只读取本步记录的审核签名，不再要求第二次签名。

【自检，逐条过】
1. 画像：数值列、分组、时间覆盖都扫过，有 profile.json
2. 热点：每条有处置（写入 / 合并 / 舍弃并说明理由）
3. 契约：每张图能说出一句话结论和支撑对象
4. 图：图号连续、图型有变化、引用与文件一一对应
5. 视觉：visual_qa 无 FAIL，预览图实际看过
6. 数字：本步产出终稿，占位符已替换；每个键名都能在 ledger.json 里找到，无裸数字
7. 解释：有出处或写「原因待核实」
8. 篇幅与措辞：以 text_stats.py 的输出为准核 规范.md（chars_body、abstract、
   每节 paras、figures、banned、bare_numbers、pages_estimate），不靠人工数
9. 送审：review_record.json 已写，state=待审核，三块材料齐全；退回意见能逐条归位

【失败处理】
- 画像跑不出来 → 检查数据文件与分组列，不带病写作
- 契约填不出 → 这张图不画，改成叙述
- 字体告警修不掉 → 换可用中文字体，不交付方框图
- 图出不来 → 删引用，不描述「应有趋势」
- 热点数据不足 → 记「无法核实」，不估算
- 送审材料写不出来 → 明确报错，不把状态改成待审核后留一份没有记录的稿
- 写完发现与底稿冲突 → 停写，回到底稿确认

【输出】
1. 数据画像摘要与 profile.json 路径
2. 热点清单：六项字段与处置
3. 图表契约与清单：图号、结论、图型、绑定键名、数据点（逐点键名与值）、文件、
   脚本路径、脚本 sha256、输出文件 sha256
4. 正文
5. 自检结果：九项逐条，附节数、图数、热点数、占位符数
6. 状态：扩写落盘后写 state=待审核；审核通过写 state=已通过（updated_by=S5）；
   交付由 S6 写 已交付，本步不生成交付包；不写状态视为未完成

【落盘】四项缺一不可；重跑前把上一版归档到 <运行目录>/history/<时间>/
- {{运行目录}}/draft.md              终稿（占位符已替换成台账 display）
- {{运行目录}}/figures_manifest.json 图表清单（图号、结论、绑定键名、逐点键名与值、
  文件路径、脚本路径、脚本 sha256、输出文件 sha256）
- {{运行目录}}/profile.json          画像结果
- {{运行目录}}/review_record.json    审核记录与送审材料
（交付包由 S6 生成到 <运行目录>/deliver/<版本>/，不在本步落盘）

【禁止】
- 不把「已修改」当成「审核通过」
- 不因为意见难改就换一种理解糊过去
- 不在意见未落实时再次送审
- 不替审核人补写意见、不虚构审核人
- 不自动放行、不宣布通过；未审核不得交付
